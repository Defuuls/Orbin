# Orbin code and design audit — November 2026

Baseline: `ae691cbe12de99692ab1f382501126c5da1f235d` (190-Puntarelle).

## Scope and evidence

This is a broad static audit of Android and iOS settings, shared Compose screens,
navigation and startup boundaries, settings persistence and backups, saved threads,
provider transports, downloads, and build/release automation. Existing settings,
feed, thread and media screenshot baselines were inspected. No repository-specific
agent instructions were present.

The selected cloud executor could not execute commands. Source was read through
the GitHub connector. Existing screenshots are fixture baselines, not renders of
these changes. This report does not establish device behavior, performance, or an
exhaustive security assessment.

## Findings addressed in this change

| Area | Problem | Change and regression coverage |
| --- | --- | --- |
| Settings design | Two unnamed groups make appearance, privacy and data actions hard to scan; settings have no search. | Named task sections on both platforms; shared search matches section, label, hint, current value and options. Secret values and text drafts are excluded. Search and registry tests cover filtering and row preservation. |
| Settings accessibility | The row and switch expose duplicate actions; the row does not expose checked state. | One labeled action with checked semantics; passive visual switch. Shared interaction test covers one callback and state changes after searching. |
| iOS controls | A 51 × 31 dp switch track has no checked semantic state and insufficient touch height. | An outer 48 dp minimum toggle target retains native track dimensions. Platform tests cover both platforms and passive switches. |
| Onboarding | Follow rows and their switches duplicate the same action. | One row toggle; interaction test verifies one action and state. |
| Backup feedback | Android reports saved searches rejected during import as restored. | Count accepted searches; test mixed valid/invalid entries in both restore modes. |
| iOS restore | Older backups can restore incomplete setup and reopen onboarding during import. | Complete setup after restore while preserving app-lock policy; regression covers older documents. |
| iOS deletion | Two-tap destructive confirmation never expires and understates what is deleted. | Match Android's four-second expiry and name history, download records and image cache. |
| Saved media | Saved audio and several video formats reload as images. | Restore supported audio/video/animated types by filename extension; roundtrip test covers playable state and URLs. |
| Provider transport | Nonstreaming requests buffer responses before the 16 MiB limit; automatic HTTP error validation also reads unbounded bodies. | Stream successful JSON within the limit and classify HTTP errors without reading their bodies. Transport regressions cover overflow before EOF and unreadable error bodies. |
| Release source | Build and publish resolve a mutable branch separately; existing tags are accepted without checking the source. | Pass the build's immutable SHA to publish; reject mismatched or changed tags before release publication. No release workflow was run. |
| Quality gates | Python regression suites and rendering dependency changes can miss their relevant checks. | Run Python tests in CI and the local check script; expand screenshot workflow paths while retaining golden verification. |

## Follow-up work

- Android deletion feedback is optimistic: success is shown before asynchronous
  clearing finishes. Add completion/error state and failure-path tests.
- Cached boards wait for stale network refresh inside `onStart`. Observe cached
  rows immediately while coordinating refresh; test cancellation and duplicate collectors.
- Android recovery still constructs parts of the database/network graph before
  crash recording and safe-mode gating. Isolate recovery dependencies and test
  startup with failing persistence construction.
- Successful pull-to-refresh has no semantic refresh action, and snackbar timing
  does not yet respect accessibility recommendations.
- iOS feedback links to GitHub issues although issues are disabled. The maintainer
  must choose a working feedback destination.
- Some design-system and README descriptions still describe removed controls or
  earlier palette behavior. Reconcile these against reachable product screens.
- Saved media classification still relies on filenames. Preserving original
  attachment type exactly would need a persistence migration.

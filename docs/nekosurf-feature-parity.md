## Reference behavior and gaps in the Orbin 209 comparison base

Visual marketing is broader than the actual rendering policy: `lib/ui/frosted.dart` uses BackdropFilter for overlays, but `lib/ui/image_frost.dart` explicitly avoids live blur behind images to prevent repeated expensive work. Match the actual reference behavior and measure scrolling; do not add per-video-frame backdrop blur to satisfy the slogan.

### Cloud sync is an iOS feature, not an Android parity requirement

Neko `CloudSync.instance` is supported only when `Platform.isIOS` (`lib/sync/cloud_sync.dart:178`); it is off by default. Turning it on first merges remote data into local state, then uploads local items absent remotely. Per-item changes/deletions flow through SyncTarget/SyncItem, not a periodically overwritten settings blob. Private CloudKit data belongs to the user's Apple account. Disabling offers keep/delete remote data; delete remains independently available. Sync logs report counts/status, not thread/filter content.

`ios/Runner/CloudSync.swift:164` checks signed entitlements AND the embedded provisioning profile before touching the container; sideloaded/non-entitled installs must degrade cleanly. Neko uses its own container. Orbin needs an Orbin container, capabilities, production schema and entitled signing, with a genuine native bridge and merge/deletion handling. Showing an iCloud switch alone is not feature completion.

**Orbin base 209: missing.** No CloudKit implementation or iCloud container is present. `storage/.../LegacySyncCleanup.kt` and `app-ios/.../LegacyKeychainCleanup.kt` deliberately remove credentials/state left by removed WebDAV/nearby sync. Do not revive those old protocols as if they were Neko iCloud behavior. Existing app lock, encryption, HTTPS and local-only defaults should remain.

### File backup reference format and the Orbin 209 gap

Neko backup is a user-initiated ZIP containing `backup.json` preferences, `media/` saved payloads and `thumbnails/` saved-video thumbnails (`lib/settings/backup.dart:11,120`). Preferences include bookmarks, history, hidden posts/filters and saved-media index. The ZIP snapshots only media that actually exists. Restore validates format before mutation, replaces portable preferences, merges saved media with deduplication/collision renaming, excludes install-local sync/private-storage state and restarts providers. Automatic `thread_copies/` cache files are not included in this backup; do not promise preserved offline snapshots merely from imported history metadata.

**Orbin base 209: partial.** `core/model/.../Backup.kt::BackupDocument` carries settings, subscribed/favorite board refs, bookmarks and saved searches. It does not carry history, per-post visibility/collapse memory, hidden filters or saved-media payloads. Neither app's current file-backup implementation exports its entire automatic offline cache. Both Android BackupService and iOS IosBackup are functional existing exports; preserve compatible old documents and validation rather than replacing them with a cosmetic Neko backup screen.

### Offline means last-loaded text, not a fully downloaded media archive

Neko `lib/history/thread_copies.dart:16` stores last-loaded JSON for each bookmarked OR history thread. Images can display only while still cached; it does not promise every attachment is kept. Per-thread writes serialize and replace atomically. Copies are pruned when neither bookmarks nor history retain their key; session history is cleared before suspension. `thread/thread_page.dart` reads that copy on fetch failure/deletion.

**Orbin base 209: partial.** `domain/.../SavedThreadRepository.kt` and its implementation support explicit saved snapshots/fallbacks. This is not automatic persistence of every bookmarked or visited thread. Adding automatic copies needs source-qualified identities, lifecycle-aware retention and clear-history behavior, not an unconditional second unbounded cache.

### Opening links: separate advertised paste navigation from outgoing browser links

Neko's advertised capability is the Open Link dialog (`lib/home/open_link_dialog.dart`). `lib/chan/board_link.dart` parses `/board/thread/id`, boards.4chan.org / boards.4channel.org, optional HTTP/HTTPS/protocol-relative links and `#p`/`#q` post fragments. The dialog currently requires a thread, fetches it and opens its OP; the parsed fragment is not itself a promise that the dialog scrolls to that post. Unsupported/failed links show errors.

Neko's Android VIEW entries are `<queries>` for launching browsers, not activity filters accepting incoming links. No OS-level universal/deep-link feature is advertised. Outgoing browser opening is separate (`lib/ui/open_url.dart`).

**Orbin base 209: paste UI missing; outgoing support present.** Android SafeExternalLinks and iOS safeExternalLink enforce safe external HTTPS. Android `IntentRoute.kt` accepts trusted notification extras and app shortcuts; those are not web deep links and their token guard must remain. Orbin's paste parser should resolve only registered providers and source-qualified board/thread IDs rather than sending arbitrary input URLs through the network client. Supporting both Orbin sites does not mean forcing all providers into 4chan's URL grammar.

### Search all 4chan has a different backend from favorite-board search

Neko uses `find.4chan.org`, through an in-app browser because Cloudflare verification/cookies are required (`lib/search/find_4chan_browser.dart`). It has cancellation, timeout and challenge interaction. Favorite-board searches use catalogs. Website marketing about no third-party collection must be read together with the privacy policy's explicit find.4chan.org and opted-in reverse-search/iCloud requests.

**Orbin base 209: all-site global scope missing.** `domain/.../search/BoardSearch.kt` and current hosts search followed board catalogs with bounded concurrency. Calling that all boards would be incorrect. Add a truthful per-provider scope/backend and retain followed-board search; do not bypass Cloudflare or silently fan out thousands of threads.

### Provider support, posting, widgets and product mapping

- Neko is a 4chan reader. Its API source uses read requests and `privacy_policy.md` explicitly says it does not post. Posting/replies/composition are not advertised features to add.
- Orbin's Vichan/LynxChan and multiple registered sites are existing Orbin features. Preserve them, with provider-qualified favorites, subscriptions, snapshots, poster filters and sync keys. Neko favorites feed does not authorize changing Orbin's explicit follow versus favorite distinction.
- Neither the website nor README advertises a home-screen widget. “Favorite boards for home-screen quick access” describes Neko's dashboard, not WidgetKit or Android widget providers. No widget work is required for advertised parity.
- Neko's Saved tab means saved attachments. Orbin's Saved destination means saved threads; these are different records. A media library can live with Orbin Downloads or a distinct collection while retaining saved threads. Renaming one destination without storing/browsing attachments does not close the feature gap.
- Neko's current release removes obsolete keep-watched-posts/video-cache-limit/recently-visited settings. Orbin can retain working Orbin controls; “all Neko features” is not a request to resurrect every obsolete Neko preference.
- No account/ads/telemetry is a product behavior; 60fps/instant/slow-network startup and exact visual matching are measured outcomes, not checkboxes established by source existence.
